# First-version integration contract

Runtime: Node 24+, built-in node:sqlite; backend ESM JavaScript under server/. Frontend React + TypeScript + Vite under src/. Production serves dist/ from the same backend. API port 4318, bind HOST env (default 127.0.0.1), PORT env. Vite development proxies /api to localhost:4318. No real career documents or personal application data are committed.

API JSON unless stated; errors {error: string}; 409 on stale revision. GET /api/health public. Auth is single-user password + HTTP-only session cookie: GET /api/session -> {authenticated,setupRequired,setupTokenRequired}; POST /api/setup {password,token?}; POST /api/login {password}; POST /api/logout. Setup token from BOARD_SETUP_TOKEN if configured; launcher opens /#setup=<token>. Frontend parses fragment, sends token, clears fragment. Password >= 10 chars. All other APIs require auth. Validate Origin on state-changing browser requests.

GET /api/board -> {opportunities: Opportunity[], settings: Settings, stages: {id,label}[]}. Stage IDs: identification, review, documents, application-review, submitted, interviews, final-interview, outcome. Outcomes: hired,rejected,ignored,withdrawn,closed (or empty string when active). GET /api/opportunities/:id -> Opportunity with arrays events,activities,documents. POST /api/opportunities -> Opportunity (201). PATCH /api/opportunities/:id accepts fields plus required revision -> updated Opportunity; if stage/outcome changed append event with effectiveAt (default now) and note. POST /api/opportunities/:id/events {note,effectiveAt?,stage?} -> updated Opportunity; PATCH /api/opportunities/:id/events/:eventId {revision,effectiveAt?,note?} -> updated Opportunity with correction history retained. POST /api/opportunities/:id/activities {kind,type,title,scheduledAt?,status,notes,contact?,isFinal?} -> updated Opportunity. PATCH /api/opportunities/:id/activities/:activityId supports reschedule and editing, required opportunity revision -> updated Opportunity. kind interview|communication; type text|phone|video|in-person|assessment|email|other; status planned|completed|cancelled. No delete endpoints needed.

Opportunity: {id,company,role,url,jobReference,location,workMode,salary,employmentType,contact,deadline,description,priority:'normal'|'high'|'low',nextAction,nextActionDate,tags:string[],stage,outcome,revision:number,createdAt,updatedAt,stageEnteredAt,events?:Event[],activities?:Activity[],documents?:Document[]}. Fields default ''. Event {id,stage,note,effectiveAt,recordedAt,corrections?:array}. Activity {id,kind,type,title,scheduledAt,status,notes,contact,isFinal,createdAt,history?:array}. Preserve original dates when corrected. Summary rendered deterministically by UI; plain-text download may use frontend Blob.

GET /api/documents -> {documents:Document[]} for reference library. POST /api/documents {opportunityId?,name,contentBase64,kind,notes?,status?} -> Document (201); kinds jd|cv|cover|reference|other; statuses draft|approved|submitted; preserve independent versions, no overwrite. GET /api/documents/:id/content streams attachment, authenticated. PATCH /api/documents/:id {status,revision?} marks document status, disallow replacing submitted content. Each document records storageRoot at upload so location changes retain old links. Document {id,name,kind,status,opportunityId,createdAt,size,version,notes,url:'/api/documents/:id/content'}.

GET /api/settings -> Settings; PATCH /api/settings accepts timezone,documentsSubdir,referenceSubdir,backupSubdir,aiEnabled:false, pendingHostPath? -> Settings. Settings {timezone,documentsSubdir,referenceSubdir,backupSubdir,hostDocumentsPath,storagePath,pendingHostPath,aiEnabled:false}. Subdir defaults opportunities,references,backups. Server rejects traversals/symlink escapes and validates writability; existing documents retain original locations. BOARD_DATA_DIR (db+pending-storage.json), BOARD_FILES_DIR (document root) are persistent; BOARD_HOST_FILES_DIR display label. Pending path request written to BOARD_DATA_DIR/pending-storage.json as {hostPath:string}, launcher applies next start/restart. Database remains local outside docs. No AI model invocation; UI shows future integration disabled, no pretend generation buttons.

GET /api/export -> JSON record/history/settings export, excludes auth and file bytes (manifest explains limitation). POST /api/backup -> {name,createdAt,location} consistent SQLite backup in filesDir/backupSubdir (DB includes auth; user treats backup as private), plus managed documents copied into snapshot folder; immutable document paths allow restore same mount locations, document portable restore a later task. Publish completed snapshots atomically; remove failed attempts. POST /api/demo optional: inserts 3 explicitly labelled fictional sample opportunities only if empty; user initiated only. UI starts genuinely empty.

Project layout: server/** contains the API and persistence layer; src/** contains the browser interface; scripts/launcher.py and board provide host lifecycle controls. Tests cover the real HTTP API and host launcher. Docker builds the frontend, then serves the production bundle and API from one container.
