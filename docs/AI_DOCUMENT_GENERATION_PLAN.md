# AI-created CV documents: handover and next implementation

**Requested 2 November 2026. Status: planned, not implemented.** This is the next priority for R7 (layout fidelity), following user confirmation that the tailoring pipeline works but the generated Word CV loses structural formatting such as a sidebar.

## What works and what is wrong

The Documents tab has compact expanders, optional cover-letter generation, automatic factual CV/evidence selection, and scrollable template/previous-CV thumbnails. Word, PDF and connected Google CVs can be selected as style references. Codex drafting and saving new files work; originals and submission snapshots are preserved.

The remaining problem is the artifact-generation architecture. AI returns Markdown text; OpKnox then builds a new Word document with `wordDraft` / `layoutDraft`. Word style copying and PDF font/page analysis preserve some typography, but rebuild the content as a linear flow. They do not preserve the selected CV's sidebar, tables, positioned elements or full page composition. More prompt wording or font extraction will not fix that structural loss.

The existing Codex bridge is deliberately a text-only adapter: tools are disabled, execution is read-only, and its contract expects JSON rather than generated document files. **Passing Markdown to that bridge is not the proposed fix.**

## Desired result

Select a previous CV and say **use this style**, then tailor the content with AI. Codex receives the actual reference files and rendered pages, creates/edits the final Word artifact, renders it, inspects the result and corrects layout issues before returning it. OpKnox presents a page preview and downloads for review, then saves those exact generated bytes. A cover letter remains optional.

- **Word reference:** edit a copy of the source package while preserving its structural layout, tables/sidebar, styles, headers/footers, graphics and page settings. Replace the relevant content without carrying over obsolete claims or personal details from the style reference.
- **PDF reference:** provide the actual PDF plus page images. Reconstruct its visual composition in an editable Word document, including the sidebar/columns and section placement; font metadata alone is insufficient. Disclose any remaining approximation.
- **Google reference:** export Word where available and provide a PDF/page rendering as visual reference. Use the same paths above.
- Preserve verified identity, employment chronology, dates and qualifications from the factual source CV. The visual reference is not automatically factual evidence. Never invent achievements or remove material history silently to fit a page count.

## Smallest implementation sequence

1. **Add a separate document-generation job to the existing Codex queue.** Reuse request tracking, progress, cancellation, deadlines and the launcher-owned helper. Keep the present text-only chat/assessment path unchanged. Verify current CLI/SDK file/image capabilities before implementing the new job contract. MCP is not a prerequisite.
2. **Prepare a bounded job folder.** Include the chosen style's original bytes, rendered reference pages, source CV, relevant evidence, role description and instructions. Record source IDs, revisions and hashes. Mount/copy inputs read-only; permit output only in the job's temporary workspace. Do not expose the whole career library, credentials or unrelated host paths.
3. **Give Codex document-authoring tools in that workspace.** Enable the narrowly scoped file/command access needed to create and render DOCX/PDF. Use available document libraries and the bundled renderer; avoid a second orchestration framework. The normal adapter's tools-disabled/read-only configuration cannot create the required artifact.
4. **Generate and visually verify.** First tailor content, then populate/reconstruct the selected layout. Render every output page and have the agent inspect the images against the reference. Correct missing sidebars, overflow, clipped text, blank pages, broken bullets and font issues. Keep generation and revision bounded, with visible progress for preparation, writing, rendering and checking.
5. **Return artifacts, not Markdown for reformatting.** Define a manifest containing relative output paths, document kind, source references, hashes, page counts and review notes. Return the finished DOCX, PDF and page images. Validate allowed paths, file sizes/types, DOCX safety and completeness before accepting them; reject missing/cancelled/late results. Never execute returned code in the app process.
6. **Preview and save the exact files.** Show the generated pages, selected reference and any layout compromises. After review, save those bytes as new draft versions and assemble the application using the existing flow. Do not run `wordDraft`/`layoutDraft` over the finished artifact. Text revisions must regenerate/update the formatted document and its previews, rather than flatten it through the old editor-save route. Approval and submission remain explicit.
7. **Handle retries and cleanup.** Preserve successful outputs for review; make repeated saves idempotent. Reject changed source references before new writes, terminate only the owned generation process on cancellation, and clean abandoned temporary job data. Keep prompts, document contents and raw reasoning out of diagnostics.

## Files and routes to inspect when resuming

- `src/components/TailorApplication.tsx`: selection, generation, editable drafts and saving.
- `server/career-buddy.mjs`: automatic source/style selection, chat generation and draft save route.
- `server/codex-local.mjs` and `scripts/codex_buddy.py`: request/response queue, current text-only contract, process permissions and output handling.
- `server/document-layout.mjs` and `server/pdf-style.mjs`: current reconstruction that loses structural layout; retain as basic-layout options, not the final writer for this new path.
- `server/document-studio.mjs`: existing renderer, page images and preview validation to reuse.
- `server/application-packs.mjs`: preserve exact generated versions and existing approval/submission behaviour.
- `scripts/launcher.py`: deploy/reload helper changes as well as the container. A previous long-running-helper reload bug caused old Codex behaviour after in-app updates; this has been fixed and must remain covered.

## Acceptance and verification

- A fictional two-column/sidebar Word reference retains its sidebar, typography, section placement and page structure after tailoring.
- A PDF version of that reference produces a visually comparable editable Word CV, including its sidebar; remaining differences are shown to the user.
- New factual content is correct and complete, and old reference-only identity/claims are absent. No silent truncation to hit two pages.
- Word and PDF previews match the exact saved artifacts; reopening, downloading or adding to an application pack does not flatten them.
- Cover letter remains optional. Existing originals, submitted versions and decisions remain unchanged.
- Test cancellation, malformed/missing files, unsafe paths/Word resources, stale sources, duplicate saves and interrupted jobs with fictional data.
- Run `npm run check`; separately record native rendering checks and a real Codex document-generation run. Existing text-response smoke tests do not prove artifact-generation success.

**Resume instruction:** Implement this document-generation path for the existing Codex integration, starting with a fictional sidebar DOCX reference. Complete generation → render → visual correction → exact-file save before extending the PDF reconstruction path. Do not start by adding more font-copying heuristics or by requiring the user to choose dozens of evidence files.
